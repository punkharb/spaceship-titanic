EDA findings (generated by 01_explore.py)

## 1. Overview
-> train has 8,693 rows and test 4,277; the only extra column in train is ['Transported']. 6 columns are numeric (Age, RoomService, FoodCourt, ShoppingMall, Spa, VRDeck); the rest are text, True/False or IDs.

## 2. Target balance
-> 50.4% of passengers were transported (4,378 vs 4,315). The classes are balanced, so accuracy is a fair main metric; a model that always guesses the majority scores only 50.4%.

## 3. Missing values
-> Each feature column is 2.1-2.5% missing in train and 1.9-2.5% in test; 24.0% of train rows have at least one gap, so dropping rows would lose too much data. We impute instead.
-> Missingness is only weakly related to the target: the largest gap is RoomService (-4.6 percentage points). Simple median/most-frequent imputation inside the Pipeline is therefore reasonable.

## 4. Data quality
-> No duplicate rows (0) or duplicate IDs (0), and no negative spending (0). Ages run 0-79; the 260 age-0 passengers are plausible babies, so we keep them.
-> CryoSleep passengers never spend (0 of 4,581) and children under 13 never spend (0 of 1,157). These are reliable row-wise rules: missing spending for them is 0, and anyone who spent > 0 was not in CryoSleep. Across both files this fills 174 missing CryoSleep values and the gaps in 578 rows with missing spending. The reverse does not hold: 9% of awake passengers also spent nothing.

## 5. Train vs test distributions
-> Category shares differ by at most 1.7 percentage points between train and test, and every numeric column has a standardised mean difference below 0.02 (< 0.1 = negligible). Test looks like train, so cross-validation scores should carry over.

## 6. Features vs target
-> Strongest categories (best-worst rate spread, ignoring groups < 30): CryoSleep 49 pp, Deck 38 pp, HomePlanet 23 pp, Destination 14 pp, VIP 12 pp, Side 10 pp. CryoSleep is the single strongest: 82% transported vs 33% awake. Deck and Side are useful, so Cabin should be split.
-> Ignored as too small to rank: {'Deck': ['T']}.
-> Spending is a strong signal: 79% of passengers with zero total spending were transported. Spending is heavily right-skewed (skewness 6-13), so log1p-transforming it makes sense, and TotalSpend summarises it in one feature.
-> Age matters at the young end: under-5s are transported 77% of the time vs 50% overall.

## 7. ID-like columns and travel groups
-> Name is 99.6% unique and Cabin 77.5% unique, so as raw values they are IDs that a model could only memorise. Drop Name and the raw Cabin (after splitting it into Deck/CabinNum/Side) and PassengerId.
-> Group size matters: solo travellers 45% transported vs 57% in groups, so GroupSize is a useful feature.
-> Group members share their features (100% of multi-person groups have one home planet) but their outcomes only slightly more than chance (44% of groups all agree vs 41% with shuffled outcomes). So the risk of a random split is mild but real: the model would be validated on the companions of people it trained on, which never happens for test.
-> 0 travel groups appear in both train.csv and test.csv (6,217 vs 3,063 groups). The train/test split keeps whole groups together, so our validation must too: this confirms the GroupKFold-by-group rule.

## 8. Decisions for src/features.py
-> Metric: accuracy as the main score (balanced classes), with F1 and ROC-AUC alongside.
-> Validation: GroupKFold by travel group (no group is in both train and test).
-> Split Cabin into Deck, CabinNum, Side; then drop Cabin, Name and PassengerId (ID-like).
-> Add GroupSize (count of the travel group within the same file) and TotalSpend.
-> log1p-transform the five spending columns and TotalSpend (heavy right skew).
-> Rule-based filling: CryoSleep=True or Age<13 -> missing spending = 0; any spending > 0 -> CryoSleep = False. These are logical rules, not learned statistics.
-> Remaining gaps (~2% per column) are imputed inside the Pipeline (median / most frequent), so imputation is learned from training folds only.
-> Do not fill values from other group members (e.g. HomePlanet), even though they always agree: that uses other rows' data, which shared rule 5 does not allow.
